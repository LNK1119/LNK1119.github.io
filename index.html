캡스톤디자인 · 2024.09 – 12 · 4인 중 임베디드 단독 담당

슬로몬 · OBD-II·페달 센서 기반 급발진 감지

Raspberry PiPythonOBD-IIOpenCVBluetooth
문제

급발진 의심 상황에서 운전자가 어떤 페달을 밟고 있었는지 객관적으로 판단할 근거가 없었습니다.

제약

라즈베리파이 한 대에서 센서, OBD, 카메라를 함께 처리해야 했고, 압력 센서는 아날로그 출력이라 바로 읽을 수 없었습니다. 오판정은 운전자를 더 혼란스럽게 만듭니다.

선택

압력값은 ADC로 변환해 읽었습니다. 신호 하나로 판정하지 않도록 브레이크 압력, 가속 페달 압력, 차량 가속도, 페달 각속도를 순서대로 확인하는 단계형 조건으로 판단하고, 판정 후 0.5초 주기로 2초간 더 모아 사용자 과실과 차량 결함을 구분했습니다.

결과·검증

센서값과 OBD 속도를 디스플레이에 실시간 출력해 판정 조건을 확인했고, 결과를 음성으로 안내했습니다. 한국정보기술학회 하계 논문경진대회 동상을 받았습니다.

판단 조건 일부pressure_brk > 200 → pressure_acc ≤ 200 → 0 ≤ accel ≤ 0.08 → |ω_pedal| ≥ 20

다시 만든다면 센서 읽기, 판단, 출력을 스레드로 나누고, 임계값을 실제 주행 데이터로 보정하겠습니다.

현대모비스 모비우스 부트캠프 PBL · 2026.02 – 03 · 5인 중 팀원

OTA 기반 첨단 차량 기능 업데이트 시스템

CANoeCAPLCANAWSV모델
문제

클라우드에서 받은 새 라이트 기능을 Telematics, VUM을 거쳐 Light ECU까지 안전하게 업데이트하는 흐름을 가상 SDV 환경에서 구현해야 했습니다.

제약

업데이트는 시동 ACC, 속도 0일 때만 가능하고, Gateway를 중심으로 한 4개 CAN 채널에서 정해진 메시지 사양(DBC)을 지켜야 했습니다.

내 담당

업데이트 조건 판단에 쓰이는 속도·조향·시동·조도 입력 ECU 4종을 CAPL로 구현해 사양대로 신호를 보냈고, 조향각에 따른 코너링 램프와 조도 기반 오토빔을 구현했습니다.

검증

요구사항 ID와 연결한 시스템 통합 테스트 10건을 수행해 업데이트 조건 판단, 진행률 표시, 롤백, 결과 기록을 시나리오별로 확인했습니다.

다시 만든다면 반복 수행한 통합 테스트를 CANoe 테스트 모듈로 자동화해 회귀 테스트를 빠르게 돌리겠습니다.
